Goa は単一の型付き Go 契約から Go サービスの API を生成するフレームワークです。ペイロード、バリデーション制約、エラーマッピング、および HTTP・gRPC・JSON-RPC のトランスポート定義を `design/*.go` に記述すると、`goa gen` がトランスポート層、各種クライアント、OpenAPI / Protobuf 仕様を `gen/` にコンパイルします。開発者が書くのは、プレーンな Go インターフェースの背後にあるビジネスロジックだけです。

- **5 分で始める：** **[動く HTTP サービスを構築する](quickstart/)**（`go install goa.design/goa/v3/cmd/goa@latest`、Go 1.27+ が必要）
- **Claude Code・Codex・Cursor をお使いですか？** **[コーディングエージェントとの開発手順](../ai-development/)**（`npx skills add goadesign/goa --skill goa-service-designer`）へ進んでください

## 1 つの契約から稼働するエンドポイントまで

### 1. 契約を設計する（`design/catalog.go`） {#phase-1-design-you-write}

```go
package design

import . "goa.design/goa/v3/dsl"

var LookupPayload = Type("LookupPayload", func() {
    Field(1, "sku", String, "Product SKU", func() {
        Pattern("^[A-Z0-9-]+$")
        Example("BOOK-1")
    })
    Required("sku")
})

var Product = Type("Product", func() {
    Field(1, "sku", String, "Product SKU")
    Field(2, "name", String, "Display name")
    Field(3, "price_cents", Int, "Price in cents", func() { Minimum(0) })
    Required("sku", "name", "price_cents")
})

var _ = Service("catalog", func() {
    Error("not_found", ErrorResult, "SKU does not exist")

    Method("lookup", func() {
        Payload(LookupPayload)
        Result(Product)
        Error("not_found")
        HTTP(func() {
            GET("/products/{sku}")
            Response("not_found", StatusNotFound)
        })
        GRPC(func() {})
    })
})
```

### 2. トランスポートとバリデーションを生成する（`gen/`） {#phase-2-generate-automated}

```bash
go mod init example.com/catalog && go get goa.design/goa/v3@v3.36.0
go run goa.design/goa/v3/cmd/goa gen example.com/catalog/design
go run goa.design/goa/v3/cmd/goa example example.com/catalog/design
```

`goa gen` は `gen/`（Git にコミットし、手編集は禁止）に以下を出力します：ハンドラー実行前に不正な SKU を拒否するリクエストデコーダー、標準の `net/http` および gRPC サーバー（リフレクション駆動のルーターではなく、生成された Go のルーティングとバリデーション）、型付き Go クライアントおよび CLI クライアント、`gen/http/openapi3.yaml`、`.proto` 定義、そしてサービスが実装する Go インターフェースです。

```go
// gen/catalog/service.go — Code generated by goa, DO NOT EDIT.
type Service interface {
    Lookup(context.Context, *LookupPayload) (*Product, error)
}
```

`goa example` は `cmd/catalog` の起動コードと `catalog.go` の雛形を初回のみ生成し、以降の編集内容を上書きしません。

### 3. ビジネスロジックを実装して起動する（`catalog.go`） {#phase-3-implement-you-write}

```go
func (s *catalogSvc) Lookup(
    ctx context.Context, p *catalog.LookupPayload,
) (*catalog.Product, error) {
    prod, ok := s.store.Get(p.Sku)
    if !ok {
        return nil, catalog.MakeNotFound(
            fmt.Errorf("unknown sku %q", p.Sku),
        )
    }
    return prod, nil
}
```

サーバーを起動して（`go run ./cmd/catalog --http-port 8080`）リクエストを送ります：

```text
$ curl -i http://localhost:8080/products/BOOK-1
HTTP/1.1 200 OK
{"sku":"BOOK-1","name":"The Go Book","price_cents":3800}
```

`design/catalog.go` のフィールドやメソッドを変更して `goa gen` を再実行すると、型が合わなくなったすべてのハンドラーと呼び出し元を Go コンパイラが即座に検出します。

## 開発者が担う範囲と Goa が生成する範囲 {#whats-hand-written-vs-auto-generated}

| 開発者とコーディングエージェントが管理（`design/`、`internal/`） | `goa gen` が自動生成（`gen/` — 変更のたびに再生成） |
| --- | --- |
| `design/` 内のドメイン型、制約、トランスポートルート | Go の型、`Service` インターフェース、エンドポイントミドルウェアフック |
| ビジネスルール、認可、永続化 | HTTP・gRPC・JSON-RPC のルーティング、コーデック、入力バリデーション |
| 冪等性、データベーストランザクション、振る舞いのテスト | 型付き Go クライアント、CLI クライアント、OpenAPI 2/3/3.2、Protobuf 仕様 |

生成されたバリデーションは、トランスポート境界で構造的な制約（`Required`、`Pattern`、`Minimum`、`Enum`）を強制します。認可、テナント境界の検査、ドメイン不変条件はサービス実装とテストで担保します。

## サービスを MCP サーバーや AI エージェントへ拡張する

[Goa-AI](../2-goa-ai/) は同じ `design/*.go` ファイルを拡張し、`MCP(...)` サーバー宣言、`BindTo` で Goa メソッドにバインドされた型付き `Toolset`、構造化出力 `Completion`、そして Temporal 上で動く永続エージェントワークフローを追加できます。
